Cross Platform Command Line and UI upgrade for OldManBeard's awesome CleanModels3 program

cleanmodels checks, repairs, compiles and decompiles Neverwinter Nights: Enhanced Edition MDL model files. It is a complete rewrite in Go: one small program per platform with nothing else to install, fast on whole folders of models, and it works the same on Windows, Linux and macOS. It comes as a command line tool and as a desktop app that has the command line tool built in.

What it does

  • Checks a model or a whole folder against 57 rules (walkmeshes, tile fade, texture coordinates, skin weights, animations, emitters, resref lengths and more) and explains each finding in plain language
  • Repairs what can be repaired automatically: walkmesh pivots, AABB trees, tilefade, degenerate faces, zero-length tangents (white streaks), robe pieces the game draws turned the wrong way when worn (a cape standing up above the shoulder), animation lengths, duplicate node names and more, listing every change it made. Shadows that tear where three or more faces meet at one edge are fixed in a binary model by changing only those faces' stored neighbours, nothing else in the file
  • Compiles ASCII to binary and decompiles binary to ASCII. The compiler follows the game's own mesh pipeline (normals, vertex merging, tangents) and is checked against models the game's compiler produced. Since 4.10, compiled models match the game's own compile on every test of a new conformance suite (animmesh animations no longer play scrambled, missing lines get the game's defaults, ASCII is read the way the game reads it). Since 4.18, every binary model in Layonara's haks (13,136 of them) survives decompile and compile again with nothing the game draws lost. A tile's walkmesh is written beside it as a .wok, as the old version did
  • Also available as a Python package (decompile, parse and compile, checked byte for byte against the program) for tools that can't run it, such as Neverblender
  • Makes a robe's, cloak's or armour part's versions for every other race and phenotype from one model, fitted to each body with the game's own data. Custom races in your haks are included. Armour parts also learn from the versions that already exist (Bioware's, or your own hand-made ones), which brings them closer to hand-made versions. Bodies of very different sizes (a custom race half a human's size) get robes and cloaks that fit, backpacks, coat tails and capes included, and a custom race with no cloaks of its own can get them too (command line: --to)
  • A compile cache for builds that compile a whole hak every time: only the models whose inputs changed (the model, its supermodels, skeleton or materials) are compiled again
  • Rescales models, snaps vertices, sets render and shadow flags and more
  • Machine readable output (JSON) for scripts and build pipelines

Application ({{app}})

  • Pick a folder (or drag one in) and run Clean, Decompile, Compile or Fix Shadows over every model in it
  • Compile can keep a cache folder, so a rebuild only compiles the models that changed (Prune cache clears out what hasn't been used for a while)
  • Per file status, a fixes column, and a details pane showing what was fixed and what was only noted
  • 3D model preview with textures: double click a file in the list
  • Make Variants (Tools menu, or right-click a robe, cloak or armour part). Every race and phenotype in one grid, each version textured on its body; wherever the body shows through, it is too tight. Click a version to adjust its width, length, shoulders, chest, waist, hips or hem with sliders (only the ones that change it are enabled); views turn and zoom together
  • ASCII and binary models are marked, and a file that can't be processed is shown as Failed with the reason
  • All the repair, transform and tile options in one panel, and save/load of your settings
  • Report a problem from the right-click menu: it sends the model to the project's issue tracker for you, no account needed

Command line ({{cli}})

  • cleanmodels check models/  (any number of files and folders; check never writes a file)
  • cleanmodels repair --all tiles/ cleaned/  (repair into a separate folder, originals untouched)
  • cleanmodels repair --open-multiedges trees/ fixed/  (fix torn shadows in binary models, nothing else changed)
  • cleanmodels compile plc_torch.mdl compiled/  (one file into a folder, or name the output file)
  • cleanmodels decompile plc_torch.mdl
  • cleanmodels compile --cache-dir ~/.cache/cleanmodels -r models/ compiled/  (only what changed is compiled; cleanmodels cache prune --unused-for 30d ~/.cache/cleanmodels clears out the rest)
  • cleanmodels variants pmh0_robe200.mdl  (every race and phenotype; add --resource-dir my_races.hak for custom races, --list-bodies to see which, --dry-run to see what it would do)
  • cleanmodels --help lists everything. The old flat flag style of CleanModels still works

Safe by default

  • An existing file is never replaced with the result for a different model unless you pass --overwrite
  • Compile always needs an output, so it can't overwrite your ASCII source by accident. To work in place, name the file twice (compile a.mdl a.mdl)
  • A file that is not a model is reported as an error instead of being treated as an empty one
  • When it can't write anything, it says so

Installation Instructions

Nothing needs installing: download the archive for your system and extract it anywhere.

  • Application (cleanmodels-qt): Windows and macOS are zip files. Linux is a .7z (x86_64 or ARM64) containing an AppImage: extract it with 7-Zip or p7zip, mark the AppImage executable (chmod +x) and run it. (On GitHub the Linux download is the AppImage itself.) Each download already contains the matching command line tool. The 3D preview needs OpenGL 3.3
  • Command line only (cleanmodels): download the zip for your system (Windows, Linux x86_64 or ARM64, macOS Intel or Apple Silicon), extract it anywhere, then run the program inside (cleanmodels-windows-amd64.exe, cleanmodels-linux-amd64 and so on; rename it to cleanmodels if you like) from a terminal
  • Compiling and variants: it reads the game's own supermodels, materials, skeletons and body parts, so it looks for your NWN install in the usual Steam and GOG folders. If yours is somewhere else, give it with --game-dir or set NWN_ROOT. Without the game's data, a model whose tangents or node numbers depend on it can compile differently, a skinned body part can't be bound to its skeleton, and variants can't be made

Coming from the Prolog version

This replaces the Prolog based engine (3.7.0) and the 0.8.0 application. Those releases are still available on the projects' GitHub pages if you need them. The Go version does not need SWI-Prolog.
